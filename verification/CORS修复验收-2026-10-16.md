# Docker 页面登录 403 修复

日期：2026-10-16。环境：本项目 `java-notebookagent` Docker Compose。

## 原因和修改

容器运行正常，直接访问 `/health` 返回 ok，但浏览器登录、注册返回 403 `Invalid CORS request`。`WebConfig` 只允许旧的 localhost:3000/5173，没有允许实际页面的 13000 端口；Nginx 转发的请求携带浏览器 Origin，触发后端 CORS 拒绝。

在允许列表中新增 `http://127.0.0.1:13000`、`http://localhost:13000`，保留原开发地址和对其他来源的限制。新增集成测试，覆盖这两个地址的预检、实际登录、带 Token 的 Notebook 列表，以及拒绝未授权来源。

修复后重新构建并创建 API/Worker 容器，保留业务数据库、上传卷、前端和其他基础设施容器。

## 已执行验证

- `mvn -q -DskipTests compile`：通过。
- `mvn -q test`：55 项，失败 0、错误 0、跳过 0；包含 18 项 BackendIntegrationTest。
- `docker compose --profile core up -d --build --no-deps --wait --wait-timeout 240 api worker`：成功，两个应用容器 healthy。
- 经前端 Nginx 入口，分别携带两个实际页面的 Origin：OPTIONS 预检 200；已有验收账号登录 200；使用返回 Token 读取 Notebook 列表 200。
- 非法注册参数返回预期的 422，而非 CORS 403；没有创建额外账号。
- 未授权 Origin 仍返回 403。
- 后端健康接口返回 ok，`/login` 页面返回 200，9 个 Compose 服务均运行。

验证仅使用原有本地验收账号，凭据和 Token 未写入本记录。本轮未调用收费模型，未重跑摄入、检索和 Agent 全流程。
