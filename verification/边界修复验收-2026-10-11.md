# Notebook 对照 Python 的边界修复（2026-10-11）

修改 Java 后端及其独立 Docker 运行配置，原 Python 项目、Notebook 前端和 .env 保持不变。

## 修复内容

1. **PDF 页码范围。** Parser 保存每页在标准化正文中的字符起止；章节和每个分块分别按字符区间相交计算页码，与 Python 的 pages_for 规则一致。包含中间空白页时仍使用 PDF 实际页号，不按 pages 列表位置计页。旧标题页号不再传播到全部后续分块。
2. **Eval 评分。** 统一裁剪空白、移除空项；来源重复项的匹配数和分母使用同一标准，分数不超过 100。空实际标题不再匹配任意来源；配置合并默认值；没有有效评分维度时 total_score=null、passed=false、status=error，并使用 score_note，与 Python 对齐。
3. **全文窗口合并。** 每个窗口记录文档、版本、字符范围和可引用证据；结论超过输入预算时分层合并，保留所有窗口来源和精确 evidence 标记。每次合并先检查实际输入预算，模型没有缩短结果或丢失引用时明确失败，避免静默截断。聚合阶段使用根系统提示及全部压缩结论，减少无关历史占用。
4. **检索降级。** 文档概要路由失败时继续全 Notebook 的分块混合检索，layered 请求标记 degraded；分块检索自身失败仍正常报错，不伪装成功。
5. **SSE 恢复。** 支持 Last-Event-ID 请求头，优先于 after；续传只返回游标之后的持久事件。非法或负游标返回 400。
6. **工具路由。** 在常驻工具及已加载 Skill allowlist 之外，对原生/MCP 工具用 SiliconFlow embedding 排序，缓存目录向量，选取最多 10 个路由候选。embedding 故障使用 Python 同类的确定性文本/中文二元组与提示词规则，并按目录顺序补齐候选；候选集保存到运行状态，审批恢复保持稳定。
7. **MCP 冷启动。** 实际重启发现 uvx 刷新下载依赖超过初始化超时。Docker 用 UV_OFFLINE=1 使用镜像构建时预装的 Semantic Scholar 依赖缓存；不限制其 HTTP 论文查询，也不影响 Java 的模型请求。需要新的 MCP 依赖时重建镜像；本地 JVM 环境未设置这个 Docker 专用变量。

## 边界

对齐的是上述行为；Java 使用 PDFBox，PDF 布局识别不保证与 Python 的解析器逐块完全相同。任务执行继续使用 Redis Streams + 数据库租约，这是 Java 版既定实现。多层合并及故障回退使用受控 provider 测试验证；真实模型验收不等于任意长文件或任意崩溃点均已穷尽。规则 Eval 不代表答案事实必然正确；Semantic Scholar 未配置 API Key 的真实查询仍可能受到第三方限流。单机样本不作为生产容量证明。
